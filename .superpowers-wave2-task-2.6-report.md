## Deviations / concerns

1. **End-to-end adapter.** The plan names "SqlAdapter on the in-memory SQL session". TODL has no in-memory SQL engine
   (only `RecordingSqlSession`, which returns canned rows and cannot assign serials / join / guard). I drove the
   end-to-end test through the `InMemoryAdapter` fake, which implements the same `WriteBatch`/Insert contract directly
   (source-assigned serial keys, optimistic guards, deletes), so it exercises the full engine → bridge → adapter
   immediate-write path, FK resolution, compensation and the optimistic conflict. The `SqlAdapter`'s
   `INSERT … RETURNING` text is covered by the dedicated SQL-adapter unit tests. If a true SqlAdapter+SQL-session
   end-to-end is required, a mini in-memory SQL session would need writing (~150–200 lines, higher risk).
2. **`EngineBridgeErrorCode.KeyNotAssigned` position.** The plan says "after `NoHomeModel`", but that enum has grown
   since (UnknownExternalBinding, SystemFieldWrite, NotOwned, InvisibleRecord) and is strictly append-only. Inserting
   after `NoHomeModel` would renumber later values, so I **appended it at the end**. Noted in a code comment.
3. **Create outcome correlation for inserts.** `WriteFailure` has no `Ref`, so per-request insert failures are signalled
   by the absence of an `Assigned` entry for the Ref (→ `KeyNotAssigned`), which is the contract the plan and the host
   (Task 2.7 `partial bulk insert reports per ref`) use. A reported `WriteFailure` without a matching Assigned entry
   lands as the same `KeyNotAssigned` outcome.
4. `src/engine-bridge/index.ts` needed no change: everything the host consumes flows through the already-exported
   model-data types (the root `@pragmatic-tech-ai/todl` re-exports `WriteOperationKind`, `WriteOperation`, `WriteResult`,
   `IDataSourceAdapter`, `KeyAssignment`), and the engine-bridge symbols (`DataSourceConnector`, `EnvironmentNodePlacement`,
   etc.) were already exported.
5. No push, no publish, no engine-repo edits (as instructed).

## Fix round 1 (review feedback)

- **Important (fixed) — `Create` orphaning rows on a mid-call adapter throw.** `Create` now applies one binding at a
  time and logs that binding's assigned inserts into the step the moment its `Apply` settles (in the same loop
  iteration), so a later binding's throw can no longer discard an earlier binding's compensation log. The per-binding
  `Apply` is wrapped in try/catch: on a throw, whatever the adapter reports it applied before dying (an `Assigned`
  array carried on the thrown error, `AssignedOf`) is logged for Undo via the shared `LogApplied` helper, then the
  throw surfaces. Index-aligned outcome mapping and Ref-keyed `Assigned` handling are unchanged.
  - New test: `create whose Apply throws after inserting still logs the applied rows for Undo`
    (`DataSourceConnectorWrite.test.ts`, new `ThrowingInsertAdapter` fake that inserts rows + assigns serials, then
    throws carrying the `Assigned`). Asserts the rows are in the source after the throw surfaces, and that `Undo`
    deletes exactly them (source empty afterwards — nothing orphans).
- **Minor — SqlAdapter.Cell coercion (concern 1 residual).** Left as-is: TODL has no in-memory SQL engine to exercise
  it closer to end-to-end (per the standing "do not add a SQL engine" directive). `SqlAdapter.Cell`'s string/number/
  boolean/null pass-through and the `String(value)` fallback are unit-covered via the canned `RecordingSqlSession`
  (`sql insert returns the assigned key` / `sql insert returns the version`); the real-SQL path (bigint/Date/etc.
  coercion) is covered by the connectors-host conformance suite (pg-mem) in Task 2.7.
- **Nits — `WriteError` and `Invalid` are now `static`** (they close over no instance state); call sites updated. The
